# Portfolio build notes

Decisions made while building the static portfolio (Phase 4). Written 2026-10-14.

## Stack and constraints

- macOS, Python 3.9 standard library only, no Node, npm, Homebrew or pandoc. So: plain HTML + CSS +
  vanilla JS. Tailwind from `cdn.tailwindcss.com` with an inline config (`darkMode: 'class'`, `brand`
  teal palette, Inter and JetBrains Mono). Lucide from unpkg. A small `styles.css` holds the parts
  Tailwind CDN does not do well (component classes, reveal animation, focus ring, timeline, print).
- All content lives in `data.js` (`window.PORTFOLIO`). `app.js` renders every section from it.
  `index.html` has only the skeleton, the SEO head, JSON-LD and the nav. Empty strings hide things:
  `person.github: ""` hides the GitHub button in the hero and contact list; project `links.live` and
  `links.repo` are hidden when empty and `links.note` shows "Private codebase, demo on request" for JobHub.
- Theme: an inline script in `<head>` applies the stored choice (localStorage, try/catch) or the system
  preference before first paint, so there is no flash. The toggle updates `aria-pressed` and its label
  and the page follows later system changes when nothing is stored.
- Reveal animation: one `IntersectionObserver`, gated behind `html.js` so content is visible without
  JavaScript, and disabled under `prefers-reduced-motion`.
- Case studies use native `<details>`/`<summary>`: keyboard and screen-reader friendly with no JS.
  Experience roles show 4 bullets and tuck the rest behind "N more".
- Lucide's current build has no brand icons, so LinkedIn and GitHub are inline SVG paths in `app.js`.
- Headless Chrome enforces a minimum window width (around 500 px), so the 390 px QA pass renders the
  page inside a 390 px iframe wrapper (`__qa_mobile.html`, deleted after QA). Screenshots were taken
  in segments by shifting the body with a negative top margin because `--screenshot` always captures
  from the document top.
- `og.png` (1200x630) was rendered from `og.html` with headless Chrome. `og.html` is kept so the image
  can be regenerated after edits; it is not linked from the site.

## Content rules followed

- Only facts from the master resume, `story.md`, `profile.json`, `README.md` and `STATE.md`. Numbers used:
  17B rows / 70-80%, 18 h to 2 h, 450M rows, 50+ SFMC automations, 67 tables / 1 TB, 10-year retention;
  JobHub figures (454 boards, 329 applications in 5 days, 138 in one day, 8 parallel agents, 25-minute
  cap, 23 modules / about 8,300 lines, 462-application outcome analysis, 59,946 USCIS employers,
  682 of 1,085 matched, about 5,000 companies harvested).
- "Availability: 2 weeks after offer" and "remote or hybrid, open to relocation" come from `profile.json`.
- Not invented: company locations for Triangulum Insights and Mindtree (left blank and hidden), the
  B.Tech location, GitHub URL, awards (none, so the Achievements section is certifications plus results).
- Visa status and salary expectations are intentionally not on the site. The JobHub case study mentions
  the USCIS sponsorship signal as a data feature only.
- Banned words and em dashes: checked with grep; none present.
- The "Key learnings" paragraphs are the only interpretive text. Each is tied to a fact in the sources.

## QA performed

See `EVALUATION.md` for the recruiter scoring. Technical checks: HTTP 200 for `/` and the PDF from
`python3 -m http.server`; every local href exists; external URLs return 200 (LinkedIn answers 999 to
automated requests, which is its bot response, not a broken link); no `<img>` without alt (there are no
`<img>` elements; all icons are `aria-hidden` SVG); no duplicate ids in the static or rendered DOM; one
`h1`; landmarks header/nav/main/aside/footer; skip link; `lang="en"`; no JavaScript console errors
(only Tailwind's CDN notice); screenshots at 1280 px and 390 px in light and dark reviewed by eye.

## Ask-me chat box (added 2026-10-19)

- `kb.js` is generated by `build_kb.py` from `data/resume.json` and `data/story.md` (plus the JobHub project
  copy already on the site). It is the chat's only knowledge; visa, salary, date of birth and address are
  never in it, and `chat.js` intercepts those questions and points to email.
- `chat.js`: BM25-style retrieval in the browser with a small synonym map, intent rules for the common
  questions (contact, years, education, certifications, roles, JobHub, "why hire you"), a tool-aware rule
  (a question naming anything on the skills lists is answered only from passages that mention it, measured
  outcomes first; if only the skills list mentions it, the answer says so rather than implying project use),
  and a refusal when nothing matches. No server, no keys.
- Voice: Whisper tiny.en through transformers.js from jsDelivr, loaded on the first mic press (about 40 MB,
  cached). Audio is captured with MediaRecorder, resampled to 16 kHz mono with OfflineAudioContext. If the
  model cannot load, the browser's SpeechRecognition is used; typing always works.
- Optional free upgrade in `chat-worker/`: a Cloudflare Worker with Workers AI (Llama 3.1 8B) phrases the
  answer from the same passages; the page falls back to the local answer on any error or after 12 seconds.
- Tested in headless Chrome with a scripted set of questions (see DECISIONS.md 2026-10-19).
- 2026-10-19 (later): the box became a plain chat. Header is just "Chat with Prashanth" with a read-aloud toggle; no
  explanatory lines. Answers are composed as first-person sentences (sentence()/joinProse()/roleSentence()): the
  company is named once, paraphrased duplicates between the resume and the story are dropped (Jaccard > 0.45), at most
  two passages per reply, yes/no questions open with "Yes." or an honest "I know X but no project was built around it".
  Voice in is tap-to-start / tap-to-stop (15 s auto-stop); voice out uses speechSynthesis, automatic after a spoken
  question and switchable in the header.
